# D29 — Every door on the lead page opens in its own browser window

_10 Sep 2026 · Sahil's ask: "a separate window wherever possible — History, for example" · chosen over a full-page view and a wider drawer_

**What it is.** History, Notes, Material sent, Paperwork, Growize account, Produce pack, Last call, Money, Reservation clock, Owners, Said to be paid, Outcome and Details — the thirteen doors `leadDoors()` can draw — now open in a real browser window (`window.open`, 560×760, resizable) instead of the 440px side drawer. A window can be dragged to a second screen and left open while the lead is worked; several can be open at once; the door stays lit while its window is open and carries a small "opens in a window" mark.

**How it works in the prototype.** The window owns no state. `popDrawer(k,id)` writes a document that carries the console's stylesheet and the same drawer body (`DRAWERS[k].body(lead)`), title and footer. Inline handlers in that body are compiled in the console (`new Function` in the opener's realm, so every name resolves to the console's globals) and attached in the window with `this` as the control — so "Save the note" in a window runs `addNote()` in the console. Every `draw()` re-renders every open window (`popRefresh()`), preserving focus and caret; the theme follows the console; Escape or `closeDrawer()` from a window's footer closes that window; a window closes itself if its lead goes out of reach; closing the console closes its windows. If the browser blocks the window, the docked drawer opens as before.

**What did not change.** The short forms — Next step, Forecast, Log a touch, Close as lost, Ask for it to be moved, Lend a page, Add a member, Who is in, Help, the checks — stay in the drawer: they are two fields and a button, and a window for them would be a window to close. The drawer code is untouched.

**Consequence for the port.** In Next.js each door is a route — `/leads/[id]/history`, `/leads/[id]/notes`, … — rendering the same feature component in a bare layout (no rail, no top bar), opened with `window.open(url, name, features)`. State is shared through the store the way it will be shared anyway: the window reads the mirror and writes through the same endpoints, and a `BroadcastChannel` (or the store's subscription) refreshes it when the console writes. The `popDrawer`/`popRender`/`popWire` trio in the prototype is the behaviour to match, not code to port.
