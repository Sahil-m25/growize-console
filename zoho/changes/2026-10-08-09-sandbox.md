## 3. What the spec cannot express (yet)

- **Leads is at its user-lookup field limit.** Creating `Leads.Supp_Requested_By` failed in the sandbox with `LIMIT_EXCEEDED`. Applied instead: `NDA_Requested_At`, `NDA_Requested_By`, `Supp_Requested_At` exist; `Supp_Requested_By` is dropped (D136: the supplementary request writes only `Supp_Requested_At`, Finance's queue shows the lead's Owner as the requester). No further user lookup can be added to Leads, which also blocks P-KAM-ACCESS (`Leads.KAM_Access`, W3-KAM-1).
- The **criteria sharing rule** (`sharingRules` supports `Record_Owner_Based` only) and "every other Leads field read-only" (P-FIN-LEADS-NDA).
- A **Cases-only Change Owner** (P-KAM-CHANGE-OWNER): `general.change_owner` has no `modules` scope (Share has).
- **Field security of the new fields.** The profile permissions each field was created with were not recorded. `planGzFields` leaves Zoho's default (read_write for every profile). Decide per field before live.
- **Receipts FLS for IR / IR Manager** and the Receipts validation rule (P-RECEIPTS-IR).
- **Module visibility has no API step.** The call used on 8-9 Oct was not recorded; the planner emits a manual step instead of guessing an endpoint.
- Request shapes marked UNVERIFIED in `fields-plan.mjs`: `userlookup` create, and picklist PATCH keeping existing values.

## 4. Replay

- Access (items 1-6): `node zoho/access/build-bundle.mjs <out.js>`; paste into the logged-in sandbox tab; `plan()`, `apply()`, `verify()`. Item 1 comes back as a manual step. `spec.pending` is stripped from the bundle.
- Fields (items 7-8): `planGzFields(currentFieldsByModule)` and `planPicklistAdds(meta)` in `zoho/sandbox/fields-plan.mjs` return the POST/PATCH steps; both are empty when the sandbox already matches.
