# D138 — Zoho changes proposed (10 Oct 2026). NOT applied to any org.

The owner's 10 Oct rulings (docs/decisions/D138-ir-money-supplementary-and-kam-ask.md) need these. Until each exists, the console
degrades and says so; nothing here was created by the session.

## A. KAM's "Ask Finance to confirm full payment" (D138 Q3)
| Module | API name | Type | Field security |
|---|---|---|---|
| LLP_UnitAllocation_Module | `Convert_Requested_At` | DateTime | read/write: KAM; read-only: Finance Ops, Finance Head, Digital Infrastructure, AM Head, C&A, Leadership, Viewer; hidden: IR, IR Manager |

- No user lookup (the module's user-lookup slots are spent since Converted_By): the requester is the Note the KAM writes on the
  Contact (Created_By / Created_Time) and the Contact's KAM.
- The KAM profile must also **read** `Supplementary_Verified_At` on the allotment (the request is refused before the signed
  supplementary, D138 Q1). If it is hidden for KAM today, make it read-only.
- Until the field exists: the request answers `fields-missing` ("Digital Infrastructure creates it"), nothing is written, and
  Finance's to-do records the problem code `confirm-requests:fields-missing`.

## B. Originating_IR on investors Finance creates (D138 Q2 answer, D137 open question 3)
- Function `gz_set_originating_ir` — draft at `zoho/deluge/gz_set_originating_ir.deluge` (copies `Origin_Lead.Owner` into an
  EMPTY `Contacts.Originating_IR`; never overwrites).
- Workflow rule **"GZ Set Originating IR"**: Contacts, on create and on edit when Origin_Lead is modified; calls the function with the
  Contact id. Its update fires the existing "GZ IR Access Sync", so IR_Access on the allotments follows.
- Backfill once: every Contact with Origin_Lead set and Originating_IR empty.
